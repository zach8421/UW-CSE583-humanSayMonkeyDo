# Quick user stories

1. Sam is a graduate student. Sam wants to connect neural data with behavior data. Sam wants to have repeatable method for analyzing data. Sam has some programming experience from class, probably intermediate level.

2. Greg is a researcher. Greg wants to use this analysis method on his own data. Greg needs to make his data compatible with the software and visualize it. Greg is a beginner programmer that is only starting to work with this dataset.

3. Mabel is the person developing the software for their work. Mabel wants to decode movements from neural data. Mabel wants to have a centralized software to process new data that gets collected and be able to visualize and quality check the data. Mabel is an intermediate programmer that understands how to work with this dataset.

4. Oliver is Mabel's PI. Oliver wants to be able to understand Mabel's workflow and reference this software in future papers. Oliver wants to be able to quality check the data and calculations and wants to follow along with the documentation. Oliver is an experienced programmer, but probably does not have the time to go through all of the code in depth. 

5. Charles is a graduate student in the same lab as Mabel. Charles wants to decode a different behavioral feature from neural data and wants to use this method. Charles needs to be able to process his data in a similar way and find compatible behavior metrics to this decoder. Charles has some programming experience from class, but has not worked with Mabel's datasets.

6. Princess is a graduate student in a fly lab. Princess wants to decode movement from neural data as well, but using different movement metrics and calcium activity. Princess needs to be able to adapt this decoder to use calcium activity instead of spiking data and change the behavior metric. Princess has some programming experience from class, probably intermediate level.
